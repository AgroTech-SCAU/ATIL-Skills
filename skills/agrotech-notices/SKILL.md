# AgroTech Innovation Lab 通知写作

将用户提供的情况写成可直接发送的中文文稿。默认交付可直接复制到微信的纯文本正文；用户需要模板、Word 或其他文件时再提供相应格式。适用场景为协会与实验室日常管理、项目协作及比赛组织，不扩展为泛用调研报告写作。

## 使用方式

先判断通知场景，再从“对应场景”定位 [成员与项目模板](references/templates.md) 或 [日常组织模板](references/daily-notices.md)，只读取需要的小节。共提供 20 类模板，可按本次任务裁剪，不把范文当作已经通过的决定或永久制度。

优先采用用户本次要求，再采用本次对话中已确认且仍适用的安排，最后参考本技能。无需反复询问用户已经给过的信息。

## 文字与版式

- 所有通知和私聊成稿均不得加粗，标题、段首、姓名、金额、日期、截止时间和正文一律适用。禁止使用 Markdown 加粗、HTML 的 b 或 strong 标签、富文本粗体；用户原稿已有加粗时也应去掉。导出为 Word 等其他格式时同样保持不加粗。
- 微信是默认发布渠道，最终文稿使用纯文本，不使用 Markdown 标题、列表、引用、反引号、代码块、Markdown 链接或表格。报名链接按用户给出的原始 URL 呈现。
- 需要突出重点时，使用自然语言、空行、中文序号（一、二、三）或 ①②③，不依赖加粗和其他富文本标记。用户提交的 Markdown 原稿也应转换为微信可直接发送的纯文本。
- 本 Skill 和参考文件使用 Markdown 组织说明，不代表生成的微信消息可以带 Markdown 标记。交付时只给消息正文，不附代码围栏。
- 默认简体中文，正式指代协会和通知落款时使用 AgroTech Innovation Lab，文中可在首次全称出现后使用 AgroTech 简称，不自行附加学校名称或未经确认的机构身份。
- 群通知通常用“标题—缘由—具体安排—联系或反馈方式—落款、日期”。短事项可合并成段落；可用一个 📢 或 ⚠️，不强制。
- 语气正式、直接、尊重；私聊回复自然简短。个人调整说明保留处理结果与依据，减少指责和情绪性判断。
- 将“踢人”“不干活”改成适合受众的“成员调整”“移出名单”“实际参与不足”“任务推进情况”。正常退出用“正常退任”，不与未履职清退混为一谈。
- “24级”等年级信息只能作为用户指定的综合考虑因素，不据此断言本人学业繁忙、不负责任或没有时间。
- 保留姓名、年级、班级、队名及项目名称的准确写法。不要自行拆分连写的班级与姓名，不将不同成员的经历混用。
- 行动要求写清谁需要反馈、向谁反馈、反馈什么、何时反馈。不要求全部成员报送材料，除非用户明确要求；此前的反馈通知仅面向长期未参与或任务长期无进展者。
- 截止时间、生效时间、申诉时间分别表述。未给定时保留【截止日期及时间】等必要占位符，不自行规定处罚期限或默认“逾期视为退出”。
- 发文日期使用当次客户端的当地日期或用户指定日期。旧范文中的日期不沿用；如用“24:00”，可同时注明次日 00:00。

## 事实与决定的边界

1. 只写用户已提供的事实、现有记录显示的情况或明确提出的计划。不要虚构复核、投票、提醒次数、工作时长、原定期限和实际产出。
2. “尚未看到进展”不等于“完全没有工作”；“进度慢”不等于“从未履职”。评价要与用户提供的材料强度相称。肯定已有贡献与说明不足可以同时成立。
3. 分清拟议决定、已共同确认的决定、已执行的操作。“打算移出”不改写成“已共同决定”；“会恢复身份”不改写成“已恢复”。
4. 若用户只提出处理意向，可直接给出“供共同确认后发送的通知稿”，不必停止写作，也不把确认手续写成已经完成的事实。
5. 区分协会成员资格、实验室名单或资源权限、具体比赛与项目参与资格。只有当次安排明确关联时才联动调整，不自行将移出实验室等同于取消协会身份。
6. 公示没有实际名单时使用“具体名单见随附名单”或【名单】，不从旧通知拼出一份所谓最终名单。

## 已确认的 AgroTech Innovation Lab 通知口径

以下为既有通知中确认过的沟通口径，用户本次明确的新要求优先：

- 被移出协会的成员是否仍可参加协会组织的比赛、软著等项目，由对应项目负责人与协会全体管理层共同讨论决定。项目负责人或单一管理人员的答复不等于最终决定。该口径已经替代早先“项目负责人单独同意即可保留名额”的表述。
- 共同决定是为了避免项目负责人独自承担去留决定的压力，也避免相关成员面对不同答复而反复沟通。把沟通集中到用户指定的负责人或协会管理层，不把正常申诉描述成施压。
- 成员身份调整不否定既有实际贡献。成果署名与贡献认定依据实际贡献；不可仅因移出名单就把已完成的贡献一并抹去。也不假定某人确实作出过贡献。
- 正常退任、暂缓参与、误判后恢复、重新申请入会是不同安排。退任不描述成惩罚；复核恢复不要求重新走一遍入会程序。
- 若文本同时出现“只有不可抗力可保留”和“课程、考试、实习可申请暂缓”，不要静默改变标准。正文可暂用“经核实后按本次规定处理”，并在文末简短标出需要统一的口径，不必因此停止其余写作。
- “重新入会需多轮面试”及“新增成员待秋招后统一公布”是此前该轮调整的安排。只有新任务仍沿用该轮安排或用户再次确认时才写入。
- 丁颖杯一轮招募曾以智能农装 ACD 题的云台、轮轨、转运、具身四队为基础，计划每队扩充至 10 人，队长候选为原队负责文书且未任原队队长的成员，优先级参考职位与协会项目贡献。这是该轮方案，不是所有比赛或下一届的固定规则。

## 日常组织通知的补充约定

- 自愿订购或自愿报名只要求有意参与者登记，明确尊重个人选择，不增加全员购买、缴费或填表要求。价格、人数和截止时间取自本次信息，不把历史会服的 55 元价格写成所有物资的默认价。
- 物资、收款、培训、活动和项目状态按已知事实表述，不把待登记写成已下单、待核对写成已收款，或为培训虚构证书、学分与参与资格。
- 按实际表格或用户要求确定登记字段，缺少字段时使用简短占位符；不把用户本机路径写进群通知，也不自动添加退款、赔偿、考核等新规则。

## 对应场景

成员管理、项目安排与私聊见 [01—08 类模板](references/templates.md)：

- 01：未参与成员反馈通知。
- 02：成员名单更新说明。
- 03：二次复查结果公示。
- 04：个人情况说明与后续安排，含委婉表述。
- 05：协会组织项目的统一调整通知。
- 06：个人项目参与资格调整通知。
- 07：比赛统一招募与队长选拔。
- 08：接受任务后恢复身份的私聊回复。

日常协作与活动组织见 [09—20 类模板](references/daily-notices.md)：

- 09：会服或物资自愿订购。
- 10：活动报名与人员招募。
- 11：会议或组会安排。
- 12：新成员欢迎与入群引导。
- 13：培训或工作坊安排。
- 14：任务分工与开放认领。
- 15：项目进度反馈与节点提醒。
- 16：材料征集、提交与补交。
- 17：物资借用与归还。
- 18：工作或项目交接。
- 19：时间、地点变更及延期、取消。
- 20：成果展示与贡献致谢。

涉及多个场景时合并必要内容，不机械拼接全部模板。用户只要求改一句、写一条回复时，直接提供相应短文。

## 交付前检查

- 所有成稿是否完全不加粗，包括标题、金额、姓名和时间；微信消息是否彻底去掉 Markdown、HTML 与富文本标记，直接粘贴即可发送。
- 人名、班级、项目、人数和日期是否准确；计划是否仍写成计划。
- 反馈对象、截止时间与联系渠道是否明确；不必要的占位符是否删去。
- 有没有虚构共同确认、已执行状态或正式规章；项目参与决定是否沿用最新共同决定口径。
- 处理结果是否清楚；事实、评价和后续安排是否彼此对应。
- 公开公示以结果和复核渠道为主；个人详细工作记录按用户指定的受众和用途呈现，不无故扩大披露范围。

默认只给可复制的文稿。确有重要口径冲突或缺项时，在正文外附一两句说明，不附冗长建议或反复要求确认。本技能提供写作支持；发送消息、删除成员、调整权限等实际操作按当次用户授权另行执行。
