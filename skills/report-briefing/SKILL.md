# 汇报信息标准化

帮助用户把“我们预计周六去一下”这类意向，整理成别人可以判断、安排和跟进的汇报

## 信息标准

按下表检查与当前事项有关的信息；这些是内容检查维度，输出采用下文的分点格式，用户另有格式要求时优先遵循

| 信息 | 应说明什么 | 需要避免的模糊表达 |
|---|---|---|
| 事项与目标 | 要做什么、为什么做、本次具体解决或验证哪个问题 | 去看看、推进一下、做个实验 |
| 时间与节点 | 具体日期、必要的起止时间；任务截止时间、准备完成时间或下次反馈节点 | 周六、近期、尽快，却没有可落实的时间 |
| 地点与对象 | 去哪个具体地点、与谁对接、针对哪台设备或哪个版本；远程工作可写系统或环境 | 那边、现场、这个设备，且上下文无法唯一识别 |
| 人员与分工 | 谁牵头、谁参与、谁配合；各组或各人的任务、人数及参加状态 | 我们、他们负责，却没有可跟进的责任人 |
| 任务与执行安排 | 做哪些具体动作、先后顺序、各组如何配合、前置条件是什么 | 人到了再说、现场再安排 |
| 资源与准备 | 所需设备、材料、数据及其准备状态；外出时补车辆、搬运、供电等实际需求 | 带设备去，却未说明设备清单或是否可用 |
| 交付与判断依据 | 最终交回什么、何时交回、凭什么判断完成；已完成工作给实际结果及证据 | 调试好了、效果不错，却没有结果或可检查的材料 |
| 问题与协调请求 | 哪些未确定或受阻、影响什么、需谁提供什么支持或作什么决定、何时需要答复 | 有点问题、还在协调，却没有具体请求 |

上述八项是基于会议要求整理的复用规范，不是领导逐字列出的八项制度；涉及会议原意或需要回查时读取 [会议依据与示例](references/meeting-basis.md)

## 整理方法

- 先判断是事前计划、进行中进展还是事后结果；优先采用用户要求的篇幅和格式
- 从用户材料及当前对话中提取已有事实，再用信息标准检查缺项；不要为凑齐字段引入无关事项
- 先交付一版可用汇报，再列影响执行、判断或决策的关键缺项；不要因为信息不全只回复问题清单
- 未提供的信息写“待确认”或“未提供”；建议用“建议”标明，不能伪装成既定安排
- 区分“拟定／待确认”“已确认”“进行中”“已完成”“受阻”等实际状态；不能把预计参与写成已确认，把计划写成完成
- “周六／明天”等相对日期仅在基准日期明确时转换为绝对日期；保留推算依据，无法唯一确定时保留原表达并标待确认，不擅自补钟点
- 人名、地名和技术名词识别不可靠时标记待核；无法可靠区分说话人时，不擅自归属发言
- 负责人应落实到可跟进的人或已明确负责的角色；材料只写某组时可以保留组名，不自行分配个人
- 允许写“验收标准待确认”，或提出标明为建议的验证办法；不自创数量、准确率、预算或截止日期

## 排版与任务对应

- 默认使用方便复制到微信的纯文本分点，避免把多项内容堆成一段；不依赖 Markdown 标题、加粗、表格、引用块或自动编号，也不默认包在代码块里
- 标题采用 `-- 日期（星期）地点／事项安排 --`；一级标题使用 `① 时间`、`② 地点` 等圈号，二级条目使用 `1、`、`2、`，段落之间留一空行
- 现场安排默认顺序为：① 时间、② 地点、③ 人员、④ 设备与准备、⑤ 本次目标、⑥ 任务分工、⑦ 现场执行安排、⑧ 预期成果与反馈；进展或结果汇报按阶段调整标题，不强套出行安排
- 地点区分出发地与目的地，有多个出发点时分别列出；人员写总人数及姓名，不从名单顺序推断上车地点、分组或负责人
- “设备与准备”集中列设备清单、车辆需求、提前搬运安排、准备责任人及各出发点联系人；只使用本次提供的联系方式，不从旧案例带入
- 先以“本次目标”建立任务列表；⑤至⑧中，同一任务保持相同序号、名称和顺序，每条采用 `序号、任务名称：内容`，分别说明目标、责任人、执行办法、交付物
- 任务数量由实际材料决定，不固定为五项；名称相近但用途或交付物不同的任务不要擅自合并；任务增删后同步调整四段中的编号
- 已有数量、单位、格式和预期标记应准确保留，例如“各 50 条”“预计 100 张”“约 15 GB”；设备型号和术语不凭猜测纠正
- 缺项直接放在相应位置，写为 `【待补充：具体需要填写的信息】`；已明确存在但未落实的事项可写 `【待确认：具体事项】`，不要只给一串笼统空栏
- 对照执行安排检查设备准备、任务分工和成果是否匹配；例如执行提到电脑而设备清单未列时，标记是否需携带待确认，不擅自断言已准备；列出的参与者未对应任务时，可提示补充角色，不自行为其分工

需要现场安排的可填写版本时，使用 [纯文本占位模板](references/field-plan-template.md)，按实际任务数量扩展；模板中的日期、人员、设备及数量均需来自本次材料

## 按汇报阶段调整重点

事前计划重点说明目标、时间地点、负责人、分工、准备状态和预期交付；涉及外出时检查谁去、怎么去、带什么、现场做什么实验，以及需要协作的组是否参加

进展汇报先说明当前结论、相对原计划完成了什么、实际结果和证据，再说明偏差或阻碍、下一步动作、责任人和反馈时间；地点和不变的背景已有共识时可省略

结果汇报先说明目标完成到什么程度，给出实际数据、照片、记录、文件或其他可检查的依据；区分已验证、失败及未验证内容，最后写遗留问题与后续安排

## 默认交付

先给可直接复制的分点汇报稿；用户需要交给他人补充时，将具体占位符放进正文对应位置，避免另列重复的缺项清单；只对影响执行或理解且不适合放正文的问题补充简短提示

用户只要求检查时，指出关键缺项并给出修改稿；用户明确要求一段话、表格或其他格式时按要求输出

仅整理、检查和起草汇报；发送消息、创建日程或分配任务需要用户另有相应指令
