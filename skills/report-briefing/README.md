# 工作汇报与现场安排 Skill

将零散工作信息整理成可执行、可跟进的中文汇报，适用于向负责人汇报工作计划、现场实验安排、进展和结果，也可检查已有汇报是否明确完整

技能名：`report-briefing`

## 适用场景

| 场景 | 整理重点 |
| --- | --- |
| 事前计划与现场安排 | 本次目标、时间地点、人员分工、设备准备、执行办法与预期成果 |
| 进行中进展 | 相对计划完成了什么、实际结果与证据、偏差或阻碍、下一步及反馈节点 |
| 事后结果 | 目标完成程度、可检查的结果、已验证与未验证内容、遗留问题和后续安排 |
| 检查与补充汇报 | 关键缺项、事实状态、负责人和成果是否清楚，给出修改稿 |

面向成员发布通知、活动招募或私聊回复时，可使用同仓库的 [agrotech-notices](../agrotech-notices/README.md)

## 安装与调用

本 Skill 位于 `skills/report-briefing/`；按[仓库安装说明](../../README.md#2-安装与使用)复制整个 Skill 子目录，确保目标目录中直接包含 `SKILL.md` 和 `references/`

默认安装在 `~/.codex/skills/report-briefing/`；如设置了 `CODEX_HOME`，则使用其下的 `skills/report-briefing/`

安装后可在新对话中调用

现场安排：

```text
用 $report-briefing 整理下面的现场实验安排，做成可直接复制到微信的纯文本分点稿
本次目标、任务分工、现场执行和预期成果按任务一一对应
未提供的信息留具体占位，不自行安排人员或补造时间和数量
【粘贴本次时间、地点、人员、设备和任务信息】
```

进展或结果汇报：

```text
用 $report-briefing 整理下面的项目进展
先说明当前结论、实际结果和证据，再写阻碍、下一步、责任人及反馈时间
区分已完成、进行中和待确认内容
【粘贴本次进展与记录】
```

检查已有汇报：

```text
用 $report-briefing 检查这份汇报，指出影响执行或判断的关键缺项，并给出修改稿
需要交给别人填写的信息放在正文对应位置，写清具体需要补什么
【粘贴原稿】
```

## 提供哪些信息

按已有情况提供事项与目标、时间与节点、地点与对象、人员与分工、任务安排、设备或资源、交付结果和待协调事项；已有原稿、名单、设备清单或记录时可直接粘贴

信息不全也可以先整理初稿；未知内容保留 `【待补充：具体信息】` 或 `【待确认：具体事项】`，建议与既定安排分开表述

## 输出约定

- 默认使用方便复制到微信的纯文本分点，不依赖 Markdown 标题、加粗、表格或代码块；用户另有格式要求时优先遵循
- 现场安排按时间、地点、人员、设备与准备、本次目标、任务分工、现场执行安排、预期成果与反馈组织
- 同一任务在目标、分工、执行和成果中保持相同序号、名称与顺序；条目数量由本次材料决定
- 多个出发点分别说明，不从名单顺序推断上车地点、分组或负责人
- 不补造人员分工、数量、设备型号、预算或截止时间，不把拟定事项写成已确认或已完成
- 相对日期只有在基准日期明确时才换算；历史会议的人员、地点、数量和安排不自动用于新任务
- 仅整理、检查和起草汇报；发送消息、创建日程和分配任务按用户当次授权执行

完整规则见 [SKILL.md](SKILL.md)；需要可填写的现场安排时使用[占位模板](references/field-plan-template.md)。[会议依据](references/meeting-basis.md)用于核对规范来源，原始录音和转写未随仓库分发
