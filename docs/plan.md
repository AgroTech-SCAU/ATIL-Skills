# 项目规划

## 目标

维护适用于 AgroTech Innovation Lab 日常沟通的写作 Skills，使常用通知有一致的组织称谓、事实边界和可复用格式

## 已有内容

- [x] `agrotech-notices` Skill 主规则与调用入口
- [x] 群通知、复查公示、成员名单调整、比赛招募等八类模板
- [x] Skill 专属说明与提示配置
- [x] 根目录使用说明与仓库协作文件

## 当前维护重点

- [ ] 对新通知需求及时核对组织名称、受众、联系人与事实依据
- [ ] 新增可复用场景时，优先更新 `agrotech-notices/references/templates.md` 并同步主规则
- [ ] 按实际安装环境检查 README 命令及目录层级
- [ ] 由维护者检查准备公开的例文是否含有不应公开的成员信息

## 内容约定

- 优先遵循用户本次提供的事实和要求，旧案例不得自动视为现行规定
- 区分拟议决定、已确认决定和实际已完成的操作
- 成员调整与项目参与资格不得未经授权自动绑定
- 正式指代组织时使用 `AgroTech Innovation Lab`，保留 `AgroTech` 作为简称
- Skill 标识保持 `agrotech-notices`，避免已有调用失效

## 后续方向

- 根据实际使用中重复出现的场景补充模板
- 保持 Skill 内容精简，避免历史通知逐渐变成未经核实的永久管理制度
- 通过 Issue 记录改进意见，经过审阅后合入主分支
